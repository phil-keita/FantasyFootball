# nflverse Data Notes

Official package: https://github.com/nflverse/nflreadpy

## Role in This Project

nflverse is the free NFL data layer for the Yardage Warriors assistant. Sleeper remains authoritative for league state. nflverse supplies actual NFL information and statistical inputs that are joined downstream using player and team identity mappings.

## Access

- Python package: `nflreadpy`
- Install: `py -m pip install -r requirements.txt`
- No API key is required.
- Data is downloaded from nflverse repositories and cached by the package.
- The package uses Polars DataFrames.
- Cache settings can be controlled with `NFLREADPY_CACHE`, `NFLREADPY_CACHE_DIR`, and `NFLREADPY_CACHE_DURATION`.

## Available Loaders

The collector uses these datasets:

```text
load_schedules
load_rosters
load_rosters_weekly
load_player_stats
load_snap_counts
load_injuries
load_depth_charts
load_ff_playerids
load_ff_opportunity
```

These provide schedules and results, team and weekly rosters, player game statistics, snap counts, injuries and practice participation, depth charts, fantasy-football ID mappings, and opportunity metrics.

## Local Collector

Run from the repository root:

```powershell
py .\nflverse_collector.py
```

The collector defaults to the latest season available from nflverse. Override it when needed:

```powershell
$env:NFLVERSE_SEASON = "2025"
py .\nflverse_collector.py
```

Output is written to:

```text
data/nflverse/<season>/
  schedules.parquet
  rosters.parquet
  rosters_weekly.parquet
  player_stats.parquet
  snap_counts.parquet
  injuries.parquet
  depth_charts.parquet
  ff_playerids.parquet
  ff_opportunity.parquet
  manifest.json
```

The manifest records the package version, collection time, row counts, and columns for each dataset.

## Current Coverage

At the time this collector was first validated, nflreadpy exposed data through the 2025 season. The Sleeper league is the 2026 season, so the collector will automatically use the latest available nflverse season until 2026 data is published. Season resolution is lazy: set `NFLVERSE_SEASON` or pass a season to the collection function when that season exists upstream.

## Projection Boundary

`load_ff_opportunity` provides useful opportunity metrics such as expected yards, touchdowns, and fantasy points. It is an input to our projection engine, not a complete guarantee of weekly fantasy projections.

The project uses FantasyPros as the initial external weekly projection
benchmark while the internal projection engine is being built. The long-term
projection workflow will be:

- Calculated internally from nflverse statistics and opportunity data
- Compared with FantasyPros provider projections
- Combined only after historical evaluation supports a blending method

The first internal model is implemented in `internal_projection.py`. It averages
the four completed weeks before the requested week from the requested season in
`ff_opportunity`, requires its `season` column, and uses
the Sleeper scoring settings for expected points, explicitly applies STD, HALF,
or PPR reception scoring, and emits the shared `ProjectionRecord` contract with
model version `nflverse-opportunity-v1`.

Every projection must record its source, model version, timestamp, and scoring assumptions.

Cross-provider identity mappings are generated by `identity_matcher.py` from
the `ff_playerids` dataset and stored in `data/identity_mapping.json`. The
matching uses provider IDs, including GSIS IDs used by opportunity rows, and
does not fall back to display names.

## Data Separation

Keep the data layers separate:

```text
Sleeper
  -> league settings, users, rosters, starters, matchups, transactions

nflverse
  -> NFL schedules, games, statistics, snaps, injuries, depth charts, IDs

Projection engine
  -> expected points, floor, ceiling, matchup metrics, simulations

LLM context builder
  -> focused evidence for start/sit, waiver, trade, and matchup decisions
```
